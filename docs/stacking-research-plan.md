# Paper-led alignment and focus stacking plan

Reviewed 2026-09-29. This plan targets automatic landscape focus stacks with two to a few frames, including multiple near-focused and multiple far-focused photographs. The current `landscape` and `landscape_blend` methods remain useful baselines. None of the learned papers below has yet been shown to improve ChimpStackr's real photographs.

Two additional automatic CPU comparisons now exist: `near_far_cut` uses an edge-aware binary graph cut for a pair, and `landscape_regions` uses multi-label alpha expansion for two to four sources. Their focus costs and source-pixel compositing are ChimpStackr adaptations of [graph-cut focus segmentation](https://journal.bit.edu.cn/zr/cn/article/doi/10.15918/j.tbit1001-0645.2015.06.017) and [alpha expansion](https://pmneila.github.io/PyMaxflow/maxflow.html). They use pinned PyMaxflow 1.3.2; neither is a reproduction of a recent trained paper or a demonstrated winner on the supplied scene.

## The failure to solve

In the supplied 300 mm scene, near fruit and branches are sharp in one frame while distant trees are sharp in the other. The failed stack contains broken fruit, irregular branch boundaries and large defocus halos. The far-focused frame also has sharp grass, so a local sharpness maximum alone cannot identify the desired foreground. Focus breathing, parallax and the lack of shared sharp features can make registration fail with “Similarity fit has too few inliers.” Alignment and focus selection must be evaluated separately and together.

Any source-selection method, learned or classical, is limited by the photographs: it cannot recover a fruit surface that is blurred in every source, or reliably reveal a background region hidden by foreground bokeh in every source. A successful automatic method should produce coherent boundaries and avoid inventing apparent photographic detail.

## Alignment papers

| Candidate | Why it belongs in the benchmark | Evidence and deployment questions |
| --- | --- | --- |
| [RoMa (CVPR 2024)](https://openaccess.thecvf.com/content/CVPR2024/html/Edstedt_RoMa_Robust_Dense_Feature_Matching_CVPR_2024_paper.html) | Dense correspondences and certainty may retain useful matches when a focus change defeats SIFT. First learned alignment candidate. | [Official code](https://github.com/Parskatt/RoMa). Generic matching scores do not establish quality on focus brackets. Check weights, runtime and Windows support. |
| [EfficientLoFTR (CVPR 2024)](https://openaccess.thecvf.com/content/CVPR2024/papers/Wang_Efficient_LoFTR_Semi-Dense_Local_Feature_Matching_with_Sparse-Like_Speed_CVPR_2024_paper.pdf) | Semi-dense correspondence is a speed and coverage comparison with RoMa. | [Official code](https://github.com/zju3dv/efficientloftr). Reproduce on the same pairs and geometry. |
| [RoMa v2 (2025 preprint)](https://arxiv.org/abs/2511.15706) | Newer dense matching with overlap and precision estimates; a research comparison after RoMa. | [Official code](https://github.com/Parskatt/RoMaV2). Its DINOv3 component has separate terms; verify those before distribution. The paper is a preprint in the repository. |
| [MASt3R (ECCV 2024)](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/09080.pdf) | 3D-grounded matches may help if the near/far separation creates repeatable parallax after global alignment. | [Official code](https://github.com/naver/mast3r). Heavier model; check checkpoint rights and practical benefit before integration. |

Use the existing SIFT similarity/ECC landscape alignment as the measured baseline. For each matcher, retain match coordinates, confidence, spatial coverage, inlier ratio and foreground/background landmark residuals. Estimate a conservative global transform from stationary, mutually visible regions, then check its residuals across the frame. Evaluate local warps only where a global transform demonstrably fails and confidence supports the correction; dense matches alone do not justify an unconstrained pixel warp. Reject implausible transforms and record the fallback. For three or more frames, align all sources to an explicit reference and validate any composed neighbor transforms.

| [SD-Fuse (Information Fusion 2026)](https://doi.org/10.1016/j.inffus.2025.104058) | Additional pair comparison focused on image structure and boundaries if DMANet/PDRFuse leave branch defects. | [Official code](https://github.com/zhaolb4080/SD-Fuse). Verify checkpoint and terms. |
| [StackMFF V2 (EAAI 2025)](https://doi.org/10.1016/j.engappai.2025.112667) | First **native multi-frame** comparison. Its focal-depth regression selects source content across an entire stack, avoiding pairwise accumulation. | [Official code and committed `model.pth`](https://github.com/Xinzhe99/StackMFF-V2). Test two, three and four images, stack order, resolution, memory and code/weight rights. |
| [DSAF-Net (Information Fusion 2024)](https://www.sciencedirect.com/science/article/pii/S1566253523004414) | Joint alignment and fusion research baseline for several misaligned focus images. | [Official code](https://github.com/PeimingCHEN/DSAF-Net). It uses a five-frame 480×360 dataset and Python 3.7/PyTorch 1.8/CUDA 11.1; landscape transfer is unproven. |
| [UHD-MFF / UMF-LUT (ECCV 2026)](https://arxiv.org/abs/2606.31242) | Relevant 4K pair paper and real/synthetic benchmark lead. | [Official repository](https://github.com/zyb5/UHD-MFF) currently has no runnable code or weights. Wait for reproducible artifacts. |

[FocusDeep and its real 30-frame RAW dataset](https://arxiv.org/abs/2311.17846) are useful for later long-burst evaluation, but its fixed long-burst setting is not the first experiment for this two-frame landscape failure. StackMFF V2 assumes frames are ordered by focal plane; multiple near and far photographs can be supplied, but capture order may need to be inferred or recorded before inference. StackMFF V3 has [a public repository](https://github.com/Xinzhe99/StackMFF-V3), but the repository describes its paper as submitted; retain it as research-only until the publication, weights and terms are verified. Reported rankings across different datasets, metrics and input resolutions are not interchangeable.

## Reproduction and implementation sequence

1. **Build a real-scene benchmark.** Preserve the original full-resolution near/far photos, the failed result and 2-, 3- and 4-frame stacks with several near/far sources. Capture sky, grass, branches, fruit, wind, parallax and 16-bit images. The chat previews alone are too small to validate a model's native-resolution edge decisions. Keep a held-out set and fixed 100% crops. Record each model's weights, preprocessing and exact source revision.
2. **Benchmark alignment independently.** Run no alignment, current landscape SIFT/ECC, RoMa and EfficientLoFTR on identical pairs. Add RoMa v2 and MASt3R if the first two leave a specific measurable failure. Record per-plane landmark error, inlier count/ratio, match distribution, valid area, transform scale, runtime and VRAM. Then apply the *same* existing fusion method to each aligned set to expose ghosting and crop regressions.
3. **Benchmark pair fusion on a fixed alignment.** Reproduce DMANet and PDRFuse with official inference and weights; add SD-Fuse for remaining boundary failures. Compare against `landscape` and `landscape_blend` using identical aligned pixels. Measure branch/fruit continuity, halos, grass contamination, ghosting, color fidelity, 16-bit output feasibility and runtime. Prefer a model's focus decision with original aligned source pixels if its reference output path reduces precision; verify this adaptation against official output.
4. **Benchmark direct multi-frame fusion.** Reproduce StackMFF V2 on two to four original sources and DSAF-Net as a joint misalignment comparison. Include sequences with several foreground and several background frames. Check order sensitivity and whether the selected source actually contains the requested detail. Do not repeatedly fuse RGB pair outputs into an N-frame result; that can compound errors and depend on order.
5. **Integrate only demonstrated wins.** Add optional paper-named alignment and stacking options to API, CLI and GUI only after reproducible real-scene improvement, supported Windows setup, verified weight rights and acceptable resource use. Keep each selected method's result separate for comparison and retain the existing landscape methods. Provide automatic confidence/fallback behavior; manual painting is outside the intended workflow.

The benchmark should report per-scene outcomes, including failures. A paper's benchmark rank alone is insufficient for this application. A shipping candidate should consistently improve held-out 100% boundary crops without materially worse alignment, crop, color or memory behavior. RoMa alignment is available as an optional experimental backend; no learned fusion backend is integrated yet.

## Reproducible external sources

Pinned package versions are preferable to floating Git branches for installable libraries. The CPU graph-cut implementation uses `PyMaxflow==1.3.2` in both Pixi and Python metadata.
